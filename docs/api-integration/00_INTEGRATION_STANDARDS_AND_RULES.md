# 📜 الأحكام العامة وقوانين ربط واجهات البرمجة (Global Integration Standards & Rules)

تحدد هذه الوثيقة الضوابط والقوانين الأساسية التي يجب الامتثال لها أثناء عملية ربط الـ API بالفرونت إند الخاص بموقع **بنك بن دول للتمويل الأصغر الإسلامي**.

---

## 🌐 1. عناوين البيئات والترويسات القياسية (Base URLs & Headers)

### عناوين البث والاتصال:
- **بيئة التطوير المحلية (Local Dev):** `http://localhost:8000/api/v1`
- **بيئة الإنتاج (Production):** `https://api.bindowalbank.com/api/v1`

### الترويسات الإلزامية (Required Headers):
يجب أن تتضمن كل طلبات الاتصال الصادرة من الفرونت إند الترويسات التالية:
```http
Accept: application/json
Content-Type: application/json
Accept-Language: ar
```
*ملاحظة: يتم تغيير قيمة `Accept-Language` تلقائياً حسب لغة الجلسة الحالية (`ar` للغة العربية أو `en` للغة الإنجليزية).*

---

## 🛡️ 2. مبادئ الحماية والاستقرار (Fault Tolerance & Graceful Fallback)

1. **عدم كسر واجهة المستخدم (Zero Broken UI Promise):**
   - يجب ألا تتسبب أي استجابة خاطئة أو بطء أو انقطاع في خادم الـ Backend في كسر الصفحة أو ظهور شاشة بيضاء.
2. **آلية البيانات الاحتياطية (Fallback Architecture):**
   - ينبغي إعداد بيانات افتراضية سليمة (Local Fallback Data) في كافة المكونات لاستخدامها تلقائياً عند فشل الطلب الشبكي.
3. **التراجع السلس والتنبيهات المستترة:**
   - تسجيل الأخطاء في منصات المتابعة أو `console.error` أثناء التطوير دون عرض التفاصيل التقنية الدقيقة للمستخدم النهائي.

---

## 🌍 3. معايير دعم اللغات المتعددة (Multilingual Standards)

- يقبل الـ Backend المعلمة `Accept-Language` لاسترجاع المحتوى بالمسمى والوصف المناسب.
- عند إرجاع كائنات تحتوي على حقول ثنائية مثل (`title_ar`, `title_en`), يتم اختيار الحقل المناسب استناداً لسياق اللغة الحالي في نظام `i18n`.

---

## ⚡ 4. التخزين المؤقت وتحسين الأداء (Caching & Revalidation)

- استخدام قدرات Next.js App Router (مثل `fetch` المدمج مع `next: { revalidate: 3600 }`) للتخزين المؤقت للبيانات شبه الثابتة مثل **قوائم التنقل والخدمات والشروط**.
- تعطيل التخزين المؤقت عند الحاجة للبيانات اللحظية أو إجراء عمليات بحث نشطة.

---

## ❌ 5. إدارة أكواد الأخطاء المتوقعة (HTTP Error Codes)

| كود الاستجابة | المعنى | طريقة التعامل في الفرونت إند |
| :-: | :--- | :--- |
| **`200 OK`** | تم الطلب بنجاح | عرض البيانات المرجعة في الواجهة. |
| **`404 Not Found`** | المورد غير موجود | توجيه المستخدم لصفحة `not-found` أو عرض تنبيه "المحتوى غير متوفر". |
| **`422 Unprocessable`** | فشل تحقق البيانات | عرض رسائل الأخطاء المحددة أسفل حقول النماذج المخصصة. |
| **`500 Server Error`** | خطأ سيرفر داخلي | التبديل الفوري للبيانات الاحتياطية (Fallback) وعرض تنبيه مؤقت إذا لزم الأمر. |
